# Портфолио — Владислав Баклан

Многостраничный сайт-портфолио: шесть разделов работ, страница «Обо мне»,
контакты. Тёмная и светлая тема, русская и английская версии, структура
заложена под французскую и испанскую.

Собран на [Astro](https://astro.build) в статический HTML. Ни сервера, ни базы
данных, ни серверного кода в рантайме — отсюда и скорость, и то, что взламывать
на сайте нечего.

```bash
npm install
npm run dev      # http://localhost:4321
npm run check    # типы и разметка
npm run build    # готовый сайт в dist/
npm run audit    # функциональная проверка сборки (см. ниже)
```

## Запускаемые копии работ

Лендинги, веб-сайты и веб-игры на сайте можно **открыть**, а не только
посмотреть на скриншоты. Копии лежат внутри портфолио, в `public/play/<slug>/`,
и открываются с того же домена — в рамке на странице проекта и в отдельной
вкладке.

```bash
npm run demos          # обновить копии из соседних папок
npm run demos -- --check   # только проверить, что источники на месте
```

`tools/sync-demos.mjs` копирует проекты из `D:/MyPortfolioProjects/<проект>`
и по дороге **выносит инлайновые `<script>` в отдельные файлы**. Без этого
пришлось бы разрешить `'unsafe-inline'` в `script-src` — ровно ту дыру, ради
закрытия которой здесь настроена строгая CSP.

Второе, что делает скрипт, — **ужимает крупные снимки**: всё, что шире
1800 px или тяжелее 320 КБ, пересжимается (`sharp`, качество 82, поворот по
EXIF). Фотографии в работах приходят прямо с телефона, а показываются в
карточке шириной в треть колонки — у Centipede Repaints это 9,3 МБ против
1,5 МБ после. Ужимается **копия, а не источник**: оригиналы остаются архивом
автора работы, и портфолио не имеет права их портить.

Список копируемых работ — в константе `DEMOS` в начале скрипта. Если папки
соседнего проекта нет, работа пропускается с предупреждением, а сборка идёт
дальше: на чужой машине этих репозиториев может не быть, но тогда ссылка
«Открыть проект» приведёт в никуда — проверяйте `npm run demos -- --check`.

Чтобы работа появилась в рамке, у неё в `src/data/projects.ts` должно быть
поле `demo` (см. `ProjectDemo` в `src/data/types.ts`). Портретным работам —
играм под телефон — задаются `ratio` и `maxWidth`, иначе рамка растянется
на всю колонку и игра станет полоской по центру пустого поля.

У копий **своя, более мягкая CSP** — см. `/play/*` в `public/_headers`.
Послаблений ровно два, и оба про оформление: таблица стилей Google Fonts и
файлы шрифтов. Скрипты по-прежнему только свои.

## Проверка перед деплоем

```bash
npm run build && npm run audit
```

`npm run audit` поднимает собранный сайт **с теми же заголовками, что отдаёт
Cloudflare**, включая строгую CSP из `public/_headers`, и прогоняет по нему
браузер: переключение темы и языка с сохранением выбора, мобильное меню,
выпадающий список разделов, всплывающие описания карточек, обход всех страниц
с проверкой ссылок, картинок и `alt`, ошибки в консоли, 404 и карта сайта.

Это не формальность. `npm run dev` заголовки из `_headers` **не применяет** —
их навешивает только Cloudflare. Поэтому поломка из-за CSP локально не видна
и проявляется лишь после деплоя. Так и нашлась реальная: Astro вшивал
небольшой скрипт прямо в HTML, CSP его блокировала, и на живом сайте
переставали работать меню, переключатель темы и появление карточек (они
стартуют прозрачными и показываются скриптом). Лечится
`vite.build.assetsInlineLimit: 0` в `astro.config.mjs` — не убирайте эту
настройку, иначе поломка вернётся.

Первый запуск требует браузера: `npx playwright install chromium`.

В переменные окружения Cloudflare стоит добавить
`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` — тогда сборка не будет тратить время на
скачивание браузера, который на сервере не нужен.

## Устройство

```
src/
  data/                 содержимое сайта
    types.ts            какие поля есть у работы и раздела
    sections.ts         шесть разделов: названия, описания, цвета

    site.ts             имя, контакты, навыки, текст «Обо мне»
  i18n/
    config.ts           список языков, пути, выбор перевода
    ui.ts               все строки интерфейса на ru и en
  lib/
    content.ts          единая точка доступа к работам для страниц
    sanity.ts           чтение из CMS
  layouts/Base.astro    общий каркас: <head>, шапка, подвал
  components/           карточки, шапка, галерея, видео, 3D-вьюер
  pages/                маршруты (см. ниже)
  scripts/site.ts       тема, меню, копирование — вся клиентская логика
  styles/global.css     дизайн-система: цвета, типографика, компоненты
public/
  _headers              заголовки безопасности для Cloudflare
  theme-init.js         ставит тему до первой отрисовки
  media/                картинки работ
studio/                 админка (Sanity Studio)
```

## Как добавить работу

Есть два пути, и они не конфликтуют: сайт берёт данные из CMS, если она
подключена, и из файла — если нет.

### Через админку (обычный способ)

Открыть Студию, нажать «Работа» → «Create», заполнить поля, нажать Publish.
Cloudflare пересоберёт сайт сам, если настроен webhook (см. ниже).

### Через файл (когда CMS ещё не подключена)

Дописать объект в массив `PROJECTS` в `src/data/projects.ts`. Обязательные
поля — `slug`, `section`, `title`, `teaser`, `summary`, `tech`, `year`.
Картинки положить в `public/media/<slug>/` и сослаться на них как
`/media/<slug>/cover.png`.

TypeScript подскажет, если что-то забыто: `npm run check`.

### Рендеры из Blender

Класть в проект исходные PNG по несколько мегабайт не нужно — их сжимает
`node tools/renders.mjs`. Скрипт делает из каждого рендера два WebP: 900px
для карточки в списке и 1920px для галереи. Новый рендер — дописать строку
в массив `FILES` внутри скрипта и запустить его заново.

### Снимки экрана мобильного приложения

`npm run screens` берёт вертикальные снимки из
`D:/MyPortfolioProjects/chto-prigotovit-android/screenshots/` и готовит из них
содержимое `public/media/chto-prigotovit-android/`: три WebP для галереи и
обложку 2160×1350 — три экрана на тёмной подложке.

Обложка именно собирается: карточка в списке работ показывает картинку в
пропорции 16/10 с `object-fit: cover`, и одиночный снимок телефона она
обрезала бы до узкой полосы из середины экрана. Новые снимки — поправить
массив `SCREENS` внутри `tools/screens.mjs`.

### Снимки лендингов

`npm run shots` переснимает картинки к страницам работ: Playwright открывает
копию из `public/play/<slug>/`, прокручивает к нужной секции и складывает
кадры в `public/media/<slug>/`. Размеры окна — 1440×900 при множителе 1.5
(даёт 2160×1350, пропорция карточки в списке работ) и 585×1266 при двойке
(телефон).

Запускать после каждой правки текста на лендинге: снимок с прошлым текстом
на странице работы врёт откровеннее, чем его отсутствие. Одну работу —
`npm run shots <slug>`. Новая работа — дописать объект в массив `JOBS`
внутри `tools/shots.mjs`.

## Тема и язык

Тема применяется скриптом `public/theme-init.js` в `<head>` **до** первой
отрисовки — поэтому при загрузке нет вспышки не той темы. Порядок решения:
сохранённый выбор → системная настройка → тёмная.

Язык на корневом `/` определяется по `navigator.languages`, но явный выбор
в переключателе запоминается и имеет приоритет.

### Как включить французский или испанский

1. Дописать перевод в `src/i18n/ui.ts` — скопировать блок `en` и перевести.
   TypeScript покажет каждый забытый ключ.
2. Перенести код языка в `ENABLED_LOCALES` в `src/i18n/config.ts`.
3. В содержимом (`src/data/*.ts` или в Студии) добавить поля `fr` / `es`.
   Незаполненные подставятся русским текстом, а не пустотой.

Маршруты, `hreflang`, карта сайта и переключатель подхватят язык сами.

## Админка (Sanity)

Схема данных уже написана, аккаунт нужно создать один раз.

```bash
cd studio
npm install
npx sanity login          # войти через Google или GitHub
npx sanity init --project-plan free
```

`init` спросит, создавать ли новый проект — согласиться, датасет назвать
`production`, схему **не** перезаписывать (она уже есть в `studio/schemas`).

После этого создать два файла с полученным идентификатором проекта:

`studio/.env`
```
SANITY_STUDIO_PROJECT_ID=ваш_id
SANITY_STUDIO_DATASET=production
```

`.env` в корне (рядом с `package.json`)
```
SANITY_PROJECT_ID=ваш_id
SANITY_DATASET=production
```

Запуск и публикация админки:

```bash
npm run dev       # админка локально на http://localhost:3333
npm run deploy    # выкладывает её на <имя>.sanity.studio
```

Доступ в админку — только у аккаунтов, которых вы пригласите в проекте Sanity.
Пароли и сессии администратора держит Sanity, на вашей стороне их нет.

### Автоматическая пересборка после правки контента

Сайт статический, поэтому после публикации в CMS его нужно пересобрать.
В Sanity: **API → Webhooks → Create webhook**, URL взять в Cloudflare Pages
(**Settings → Builds & deployments → Deploy hooks**), метод POST, датасет
`production`, триггеры Create / Update / Delete.

## Деплой на Cloudflare Pages

1. Залить репозиторий на GitHub.
2. В Cloudflare: **Workers & Pages → Create → Pages → Connect to Git**,
   выбрать репозиторий.
3. Настройки сборки:
   - Framework preset: **Astro**
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Переменные окружения: `SANITY_PROJECT_ID`, `SANITY_DATASET` — если CMS подключена.
4. После первого деплоя заменить адрес в `astro.config.mjs` (`site`) и в
   `public/robots.txt` на настоящий — от него зависят канонические ссылки,
   `hreflang` и карта сайта.

Свой домен подключается в **Custom domains**; сертификат выпускается сам.

## Безопасность

Статический сайт снимает большую часть рисков: нет ни базы, ни серверного
кода, ни формы входа, которую можно подобрать.

Что настроено сверх этого — в `public/_headers`:

- **CSP** — скрипты только со своего домена (`script-src 'self'`), никаких
  инлайновых скриптов. Плееры YouTube и Vimeo разрешены только во фреймах и
  подключаются лишь после клика.
- **X-Frame-Options / frame-ancestors** — сайт нельзя открыть во фрейме
  на чужом домене. Запускаемым копиям работ (`/play/*`) разрешён фрейм со
  своего домена — иначе рамка на странице проекта осталась бы пустой.

Заголовки расписаны **по путям**, а не одним блоком `/*`. Это сделано
намеренно: у страниц портфолио и у копий работ разные политики, а если один и
тот же заголовок придёт из двух подходящих правил, браузер применит обе
политики сразу и возьмёт самую строгую — послабление для `/play/*` тихо
перестало бы действовать. Пересечений между правилами нет, поэтому добавляя
новое, следите, чтобы оно не начало перекрываться с соседним.
- **HSTS** — только HTTPS.
- **Permissions-Policy** — камера, микрофон, геолокация и платежи отключены.
- **X-Content-Type-Options** — запрет угадывания типа файла.

Проверить после деплоя: [securityheaders.com](https://securityheaders.com).

Отдельно: `.env` не попадает в git, а токен записи Sanity сайту не нужен —
он читает публичный датасет анонимно.
