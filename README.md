# Портфолио — Владислав Баклан

Многостраничный сайт-портфолио: шесть разделов работ, страница «Обо мне»,
контакты. Тёмная и светлая тема, русская и английская версии, структура
заложена под французскую и испанскую.

Собран на [Astro](https://astro.build) в статический HTML. Ни сервера, ни базы
данных, ни серверного кода в рантайме — отсюда и скорость, и то, что взламывать
на сайте нечего.

```bash
npm install
npm run dev      # http://localhost:4321
npm run check    # типы и разметка
npm run build    # готовый сайт в dist/
```

## Устройство

```
src/
  data/                 содержимое сайта
    types.ts            какие поля есть у работы и раздела
    sections.ts         шесть разделов: названия, описания, цвета
    projects.ts         сами работы (запасной источник, если CMS не подключена)
    site.ts             имя, контакты, навыки, текст «Обо мне»
  i18n/
    config.ts           список языков, пути, выбор перевода
    ui.ts               все строки интерфейса на ru и en
  lib/
    content.ts          единая точка доступа к работам для страниц
    sanity.ts           чтение из CMS
  layouts/Base.astro    общий каркас: <head>, шапка, подвал
  components/           карточки, шапка, галерея, видео, 3D-вьюер
  pages/                маршруты (см. ниже)
  scripts/site.ts       тема, меню, копирование — вся клиентская логика
  styles/global.css     дизайн-система: цвета, типографика, компоненты
public/
  _headers              заголовки безопасности для Cloudflare
  theme-init.js         ставит тему до первой отрисовки
  media/                картинки работ
studio/                 админка (Sanity Studio)
```

### Маршруты

| Адрес | Что это |
| --- | --- |
| `/` | определяет язык браузера и уводит на `/ru` или `/en` |
| `/ru`, `/en` | главная |
| `/ru/about` | обо мне и навыки |
| `/ru/contacts` | контакты и фриланс-площадки |
| `/ru/privacy` | политика конфиденциальности |
| `/ru/work/<раздел>` | список работ раздела |
| `/ru/work/<раздел>/<работа>` | страница работы |

Разделы: `landings`, `websites`, `web-games`, `pc-games`, `mobile-apps`,
`models-3d`.

## Как добавить работу

Есть два пути, и они не конфликтуют: сайт берёт данные из CMS, если она
подключена, и из файла — если нет.

### Через админку (обычный способ)

Открыть Студию, нажать «Работа» → «Create», заполнить поля, нажать Publish.
Cloudflare пересоберёт сайт сам, если настроен webhook (см. ниже).

### Через файл (когда CMS ещё не подключена)

Дописать объект в массив `PROJECTS` в `src/data/projects.ts`. Обязательные
поля — `slug`, `section`, `title`, `teaser`, `summary`, `tech`, `year`.
Картинки положить в `public/media/<slug>/` и сослаться на них как
`/media/<slug>/cover.png`.

TypeScript подскажет, если что-то забыто: `npm run check`.

### Рендеры из Blender

Класть в проект исходные PNG по несколько мегабайт не нужно — их сжимает
`node tools/renders.mjs`. Скрипт делает из каждого рендера два WebP: 900px
для карточки в списке и 1920px для галереи. Новый рендер — дописать строку
в массив `FILES` внутри скрипта и запустить его заново.

## Тема и язык

Тема применяется скриптом `public/theme-init.js` в `<head>` **до** первой
отрисовки — поэтому при загрузке нет вспышки не той темы. Порядок решения:
сохранённый выбор → системная настройка → тёмная.

Язык на корневом `/` определяется по `navigator.languages`, но явный выбор
в переключателе запоминается и имеет приоритет.

### Как включить французский или испанский

1. Дописать перевод в `src/i18n/ui.ts` — скопировать блок `en` и перевести.
   TypeScript покажет каждый забытый ключ.
2. Перенести код языка в `ENABLED_LOCALES` в `src/i18n/config.ts`.
3. В содержимом (`src/data/*.ts` или в Студии) добавить поля `fr` / `es`.
   Незаполненные подставятся русским текстом, а не пустотой.

Маршруты, `hreflang`, карта сайта и переключатель подхватят язык сами.

## Админка (Sanity)

Схема данных уже написана, аккаунт нужно создать один раз.

```bash
cd studio
npm install
npx sanity login          # войти через Google или GitHub
npx sanity init --project-plan free
```

`init` спросит, создавать ли новый проект — согласиться, датасет назвать
`production`, схему **не** перезаписывать (она уже есть в `studio/schemas`).

После этого создать два файла с полученным идентификатором проекта:

`studio/.env`
```
SANITY_STUDIO_PROJECT_ID=ваш_id
SANITY_STUDIO_DATASET=production
```

`.env` в корне (рядом с `package.json`)
```
SANITY_PROJECT_ID=ваш_id
SANITY_DATASET=production
```

Запуск и публикация админки:

```bash
npm run dev       # админка локально на http://localhost:3333
npm run deploy    # выкладывает её на <имя>.sanity.studio
```

Доступ в админку — только у аккаунтов, которых вы пригласите в проекте Sanity.
Пароли и сессии администратора держит Sanity, на вашей стороне их нет.

### Автоматическая пересборка после правки контента

Сайт статический, поэтому после публикации в CMS его нужно пересобрать.
В Sanity: **API → Webhooks → Create webhook**, URL взять в Cloudflare Pages
(**Settings → Builds & deployments → Deploy hooks**), метод POST, датасет
`production`, триггеры Create / Update / Delete.

## Деплой на Cloudflare Pages

1. Залить репозиторий на GitHub.
2. В Cloudflare: **Workers & Pages → Create → Pages → Connect to Git**,
   выбрать репозиторий.
3. Настройки сборки:
   - Framework preset: **Astro**
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Переменные окружения: `SANITY_PROJECT_ID`, `SANITY_DATASET` — если CMS подключена.
4. После первого деплоя заменить адрес в `astro.config.mjs` (`site`) и в
   `public/robots.txt` на настоящий — от него зависят канонические ссылки,
   `hreflang` и карта сайта.

Свой домен подключается в **Custom domains**; сертификат выпускается сам.

## Безопасность

Статический сайт снимает большую часть рисков: нет ни базы, ни серверного
кода, ни формы входа, которую можно подобрать.

Что настроено сверх этого — в `public/_headers`:

- **CSP** — скрипты только со своего домена (`script-src 'self'`), никаких
  инлайновых скриптов. Плееры YouTube и Vimeo разрешены только во фреймах и
  подключаются лишь после клика.
- **X-Frame-Options / frame-ancestors** — сайт нельзя открыть во фрейме
  на чужом домене.
- **HSTS** — только HTTPS.
- **Permissions-Policy** — камера, микрофон, геолокация и платежи отключены.
- **X-Content-Type-Options** — запрет угадывания типа файла.

Проверить после деплоя: [securityheaders.com](https://securityheaders.com).

Отдельно: `.env` не попадает в git, а токен записи Sanity сайту не нужен —
он читает публичный датасет анонимно.
